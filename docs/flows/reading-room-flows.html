How Reading Room works

Every button in the app, followed from the click in the browser down to the rows in PostgreSQL and back. Part 1 animates the main journeys and can save them as a video. Part 2 shows the whole system together, Part 3 has a diagram for every function, and Part 4 maps every endpoint. Every step names the real file and function it runs.

1. Watch it run 2. The whole system 3. Every function 4. Endpoint map

1. Watch it run

Pick a journey and press Play. Each arrow is one call between two parts of the system, and the caption explains what it does. Save video records the animation to a .webm file (plays in Chrome, Edge, VLC). Keep this tab visible while it records, because browsers pause animations in background tabs.

    2. The whole system, together

    Requests always travel the same way: React page → api/client.js → Vite proxy → FastAPI router → core/security.py → a service → PostgreSQL. Routers handle only HTTP, services hold every rule, and every write also adds a row to activity_log.

    3. Every function, one at a time

    Each diagram is one button or one API call. Numbers on the arrows show the order. alt boxes are if/else branches; opt boxes only run sometimes.

    4. Endpoint map

    All routes are mounted under /api in backend/app/main.py. "Writes" lists the tables a call changes, and every write also inserts into activity_log.
